# M2 后端协作与说明维护约定

本目录只覆盖 M2 课程推荐。不要为了说明 M2 扩写或修改其他成员的业务模块。

## 先理解再修改

1. 先读 [后端 README](README.md) 的调用链和阅读顺序，再读 `CODE_GUIDE.md` 中目标 Java 类的章节。
2. 查看 `git status`，保留已有未提交工作。本文不是要求重置、自动提交或推送代码。
3. 明确改动属于请求合同、资格规则、评分、模型通信或数据保存，避免把职责塞进不相关层。

## 每个源码文件的说明要求

- 类注释写明“为什么需要、由谁调用、交给谁处理”。关键方法注释解释意图和边界，而不是逐字翻译语法。
- `CODE_GUIDE.md` 中保留 14 个 Java 文件一一对应的章节，不再为每个类建立独立文件，列出输入输出、关键方法、设计理由和验证入口。
- 数据字段变化同步检查 Mapper 别名、前端和历史 JSON；新增方法或变更限制时同步说明，不能继续保留失实文档。
- 明确区分代码已经实现的检查、模拟测试和真实供应商 / 数据库验证，不把计划写成完成状态。

## M2 必须保持的业务边界

- 使用团队 Java 8 / Spring Boot 2.6.3 和现有 Session，身份来自服务器；请求不能自行传入已修记录替代数据库成绩。
- 不绕过 `Recommender.eligible`，不同先修组为 AND，组内为 OR；未审核不等于无要求。
- 原推荐接口继续返回数组，辅助接口返回模式信封；缺配置、供应商错误和非法输出时明确回退。
- 密钥仅在后端环境中；不放到 Java 常量、Vue、日志、仓库或说明文件。供应商只收到必要查询和公开课程摘要。
- 外部网络调用在写事务之前；画像和历史通过独立 `CourseHistoryWriter` 原子保存，继续兼容旧历史。

## 检查修改

先运行 README 的定向 Java 测试；涉及 SQL、归属或事务时再使用隔离的真实 MySQL 测试。文档修改后检查相对链接和源码覆盖情况。`AGENTIC.md` 是普通协作文档，使用 AI 工具时主动引用，不能假设它会被自动加载。
