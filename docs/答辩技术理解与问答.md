# 高校宿舍管理系统答辩技术理解与问答文档

## 1. 项目总体介绍

本项目是一个高校宿舍管理系统，解决宿舍管理中“人员、房间、床位、申请、费用、检查、通知”分散记录的问题。系统把学生账号、宿舍管理员账号、宿舍楼、房间床位、公告、报修、调宿、水电费、卫生检查、访客登记统一放到一个后台系统里管理。

系统主要有三种角色：

- 管理员：维护学生、宿管、宿舍楼、房间、公告、报修、调宿、水电费、卫生检查、访客和权限说明。
- 宿舍管理员：维护学生、宿舍楼、房间，处理报修、调宿、访客登记和卫生检查。
- 学生：查看个人宿舍，提交报修和调宿申请，查看水电费和卫生检查记录，维护个人资料。

项目采用前后端分离，因为 Vue 前端负责页面展示、表格、表单和路由跳转，Spring Boot 后端负责接口、业务逻辑、Session 和数据库读写。这样前端和后端可以独立启动、独立调试，也符合课程要求的 Spring Boot + MySQL 8.0 + Vue 3 + Vite 技术栈。

本项目适合作为跨平台开发课程大作业，因为它不是只能在某一台电脑上运行的桌面程序，而是 Web 应用。PC 浏览器访问 `http://localhost:8080` 可以使用完整后台界面，手机浏览器访问电脑局域网 IP 加端口也可以打开同一套系统。移动端适配主要通过 `vue/src/assets/css/global.css`、`vue/src/layout/Layout.vue`、`vue/src/components/Aside.vue`、`vue/src/views/Home.vue` 等文件中的媒体查询和响应式布局实现。

## 3. 系统架构说明

系统架构可以按下面的数据链路理解：

```text
PC 浏览器 / 手机浏览器
  -> Vue 3 + Vite 前端页面
  -> Axios 请求封装 vue/src/utils/request.js
  -> Vite 代理 /api 到 http://localhost:9090
  -> Spring Boot Controller
  -> Service 业务层
  -> Mapper / MyBatis-Plus / JdbcTemplate
  -> MySQL 8.0 dormitory 数据库
```

一次完整请求示例：管理员查询学生列表。

1. 用户打开 `vue/src/views/StuInfo.vue`。
2. 页面加载时引入 `vue/src/assets/js/StuInfo.js`，`created()` 中调用 `load()`。
3. `load()` 调用 `request.get("/stu/find", { params: { pageNum, pageSize, search } })`。
4. `vue/src/utils/request.js` 给请求加上 `/api` 前缀，浏览器实际访问 `/api/stu/find`。
5. `vue/vite.config.js` 把 `/api/stu/find` 代理到 `http://localhost:9090/stu/find`。
6. 后端 `springboot/src/main/java/com/example/springboot/controller/StudentController.java` 的 `@GetMapping("/find")` 接收请求。
7. Controller 调用 `StudentService.find(pageNum, pageSize, search)`。
8. `StudentServiceImpl.java` 创建 `Page` 和 `QueryWrapper<Student>`，用 `studentMapper.selectPage(page, qw)` 查询。
9. `StudentMapper.java` 继承 `BaseMapper<Student>`，由 MyBatis-Plus 生成 SQL 查询 `student` 表。
10. MySQL 返回分页结果。
11. 后端用 `Result.success(page)` 包装成 JSON。
12. 前端拿到 `res.data.records` 和 `res.data.total`，渲染 Element Plus 表格和分页。

## 4. 数据库设计详解

数据库脚本在 `database/` 目录中：

- `database/dormitory_mysql8.sql`：创建 `dormitory` 数据库、业务表、权限表，并插入基础账号和基础数据。
- `database/permission_tables.sql`：单独重建权限三张表，适合给已有数据库补权限菜单。
- `database/test_data.sql`：可重复导入的测试数据，覆盖学生、宿管、宿舍、公告、报修、访客、水电、卫生检查、调宿申请。

## 5. 数据是怎么进入数据库的

### 5.1 初始化数据

首次初始化执行：

```bash
mysql -uroot < database/dormitory_mysql8.sql
```

这个脚本会创建数据库 `dormitory`，删除旧表后重建全部表，并插入基础数据：

- `admin`：插入 `admin / 123456`。
- `student`：插入 `stu1 / 123456`、`stu2 / 123456`。
- `dorm_manager`：插入 `dorm1 / 123456`。
- `dorm_build`：插入一号楼、二号楼。
- `dorm_room`：插入 101、102、201 房间和床位信息。
- `notice`、`repair`、`dorm_water`、`dorm_electric`、`dorm_check`：插入基础演示数据。
- `sys_role`、`sys_menu`、`sys_role_menu`：插入三种角色、菜单和角色菜单关系。

补充测试数据执行：

```bash
mysql -uroot < database/test_data.sql
```

这个脚本先删除测试账号和测试房间相关数据，再插入：

- 测试学生：`test_stu01` 到 `test_stu05`。
- 测试宿管：`test_dorm03`、`test_dorm04`。
- 测试宿舍楼：三号楼、四号楼。
- 测试房间：301、302、401、402。
- 测试公告、报修、访客、水费、电费、卫生检查、调宿申请。

单独补权限表执行：

```bash
mysql -uroot < database/permission_tables.sql
```

它只重建 `sys_role`、`sys_menu`、`sys_role_menu`，适合旧数据库已经有业务表时补上动态菜单能力。

## 6. 前后端通信机制

Axios 配置在 `vue/src/utils/request.js`：

- `baseURL: "/api"`
- `timeout: 5000`
- `withCredentials: true`
- 请求拦截器：挂在 `request.interceptors.request`，会尝试读取 `sessionStorage` 中的 `access-user` 并设置 `headers.token`。当前项目主要使用 Session/Cookie，token 不是主要认证方式。
- 响应拦截器：统一返回 `response.data`，如果是字符串则尝试 JSON 解析。

Vite 配置在 `vue/vite.config.js`：

```js
server: {
  host: '0.0.0.0',
  port: 8080,
  proxy: {
    '/api': {
      target: 'http://localhost:9090',
      changeOrigin: true,
      rewrite: path => path.replace(/^\/api/, '')
    }
  }
}
```

所以前端写 `request.get("/stu/find")`，浏览器访问的是 `/api/stu/find`，Vite 开发服务器转发到后端 `http://localhost:9090/stu/find`。

后端当前没有单独的 CORS 配置类，开发阶段主要靠 Vite 代理解决跨域。登录后后端通过 Session 保存状态，浏览器保存 Session Cookie。因为 `request.js` 设置了 `withCredentials: true`，同源代理访问时 Cookie 会参与请求。

三个真实接口例子：

| 前端请求 | 后端接口 | 参数 | 返回 | 页面使用 |
| --- | --- | --- | --- | --- |
| `Home.js` 请求 `/stu/stuNum` | `StudentController.stuNum` | 无 | `{"code":"0","data":7}` | 首页学生统计卡片 |
| `RoomInfo.js` 请求 `/room/find` | `DormRoomController.findPage` | `pageNum,pageSize,search` | MyBatis-Plus `Page` | 房间表格 |
| `Aside.vue` 请求 `/permission/menus` | `PermissionController.menus` | Session 中的 `Identity` | 菜单树 | 侧边栏动态菜单 |

页面空白或请求失败排查顺序：

1. 看前端终端 `npm run dev` 是否启动成功。
2. 打开浏览器控制台，看是否有 JavaScript 报错。
3. 看 Network 中 `/api/...` 是否 200。
4. 直接 curl 后端接口，例如 `curl http://localhost:9090/stu/stuNum`。
5. 检查 8080 和 9090 端口是否跑的是当前项目。
6. 检查 `sessionStorage` 是否有 `user` 和 `identity`。
7. 检查 MySQL 是否有数据。

## 7. 登录、Session、Cookie 和权限控制

登录页面在 `vue/src/views/Login.vue`，逻辑在 `vue/src/assets/js/Login.js`。

登录流程：

1. 用户填写账号、密码，并选择学生、宿舍管理员或系统管理员。
2. 前端根据身份拼接接口：`request.post("/" + this.identity + "/login", this.form)`。
3. 学生登录进入 `StudentController.login`，查询 `student` 表。
4. 宿管登录进入 `DormManagerController.login`，查询 `dorm_manager` 表。
5. 管理员登录进入 `AdminController.login`，查询 `admin` 表。
6. Service 使用 MyBatis-Plus `QueryWrapper` 按 `username` 和 `password` 查询。
7. 登录成功后，后端执行 `session.setAttribute("Identity", "...")` 和 `session.setAttribute("User", o)`。
8. 浏览器保存服务端返回的 Session Cookie。
9. 前端保存 `sessionStorage.user` 和 `sessionStorage.identity`，并跳转 `/home`。

刷新页面后，前端 `sessionStorage` 仍在，路由守卫会允许访问。侧边栏 `Aside.vue` 会请求 `/main/loadIdentity` 和 `/main/loadUserInfo` 尝试从后端 Session 恢复身份；如果后端 Session 丢失，则用 `sessionStorage` 中缓存的信息兜底，并使用 `fallbackMenus` 防止菜单空白。

退出登录在 `vue/src/components/Header.vue`：

- 前端 `sessionStorage.clear()`。
- 请求 `/main/signOut`。
- 后端 `MainController.signOut` 移除 Session 中的 `User` 和 `Identity`。
- 前端跳转 `/Login`。

未登录拦截在 `vue/src/router/index.js`：

- 如果访问 `/Login`，直接放行。
- 如果没有 `sessionStorage.user`，跳转 `/Login`。
- 登录后访问 `/`，跳转 `/home`。

动态菜单重点：

- `sys_role` 保存 `admin`、`dormManager`、`stu` 三种角色。
- `sys_menu` 保存菜单名称、路由、图标、排序、权限标识。
- `sys_role_menu` 保存角色与菜单的对应关系。
- `/permission/menus` 在 `PermissionController.java` 中，根据 Session 的 `Identity` 查询菜单。
- 后端用 `JdbcTemplate` 查询 `sys_menu` 和 `sys_role_menu`，再组装成父子菜单树。
- 前端 `Aside.vue` 用 `v-for` 渲染一级菜单和二级菜单。

新增一个菜单需要改：

1. 在 `sys_menu` 插入菜单记录，设置 `menu_path` 对应前端路由。
2. 在 `sys_role_menu` 给角色分配菜单。
3. 在 `vue/src/router/index.js` 添加路由。
4. 新建或复用 `vue/src/views/*.vue` 页面和 `vue/src/assets/js/*.js`。
5. 如果页面需要数据，新增或复用后端 Controller、Service、Mapper、Entity。

## 12. 常见问题排查

### 12.1 前端页面空白

- 前端依赖没安装：进入 `vue/` 执行 `npm install`。
- Vite 没启动：执行 `npm run dev`，确认有 `Local: http://localhost:8080/`。
- 路由路径错误：本项目登录页是 `/Login`，已添加 `/login` 重定向。
- 接口请求失败：浏览器 Network 看 `/api/...` 是否 200。
- 登录状态失效：检查 `sessionStorage.user` 和 `sessionStorage.identity`。
- JavaScript 报错：打开控制台 Console，根据报错定位组件。
- 后端没启动：访问 `http://localhost:9090/stu/stuNum` 或用 curl 测试。

### 12.2 登录失败

- 确认数据库中有账号，例如 `admin/123456`。
- 确认选择了正确身份，管理员必须选“系统管理员”。
- 后端 9090 是否启动。
- MySQL 连接配置是否正确。
- 浏览器请求 `/api/admin/login`、`/api/stu/login` 或 `/api/dormManager/login` 是否成功。
- Session/Cookie 是否被保存，开发阶段建议通过前端 8080 代理访问。

### 12.3 菜单不显示

- 当前用户是否登录。
- `sessionStorage.identity` 是否是 `admin`、`dormManager` 或 `stu`。
- `/permission/menus` 是否返回 `code: "0"`。
- `sys_role_menu` 是否有对应角色菜单数据。
- `Aside.vue` 是否正确渲染返回的 `children`。
- 如果后端 Session 失效，前端会使用 `fallbackMenus` 兜底。

### 12.4 数据新增后页面不显示

- 看 Network 是否真的发出 POST 请求。
- 看接口返回是否 `code: "0"`。
- 后端 Controller 是否进入对应方法。
- 数据库表是否真的新增记录。
- 新增后前端是否调用了 `load()` 刷新表格。
- 搜索条件是否过滤掉了新增数据。

### 12.5 后端连接不上数据库

- MySQL 是否启动：`brew services start mysql`。
- 数据库是否存在：`mysql -uroot -e "SHOW DATABASES;"`。
- 数据库名是否为 `dormitory`。
- `application.properties` 中用户名密码是否正确。
- MySQL 8 驱动是否匹配：当前使用 `com.mysql.cj.jdbc.Driver`。
- 端口 3306 是否可用。

答：有管理员、宿舍管理员和学生三种角色，角色通过 `sys_role` 表维护。

4. 问：管理员能做什么？  
答：管理员基本拥有全部菜单，可以维护账号、宿舍、公告、报修、调宿、访客、水电费、卫生检查和权限说明。

5. 问：学生能做什么？  
答：学生可以查看自己的宿舍，提交报修和调宿申请，查看水电费和卫生检查，维护个人资料。

### 13.2 前后端通信类

6. 问：前后端如何通信？  
答：前端通过 Axios 发送 `/api` 请求，Vite 把 `/api` 代理到 Spring Boot 的 `localhost:9090`。

7. 问：Axios 在哪里封装？  
答：在 `vue/src/utils/request.js`，配置了 `baseURL: "/api"`、响应拦截器和 `withCredentials`。

8. 问：后端接口返回什么格式？  
答：统一用 `Result` 封装，包含 `code`、`msg`、`data`。

9. 问：跨域怎么解决？  
答：开发阶段用 Vite 代理解决，配置在 `vue/vite.config.js`，把 `/api` 转发到 `http://localhost:9090`。

10. 问：如果后端端口改了，前端改哪里？  
答：改 `vue/vite.config.js` 里 proxy 的 `target`。

### 13.3 数据库类

11. 问：数据库叫什么？  
答：数据库名是 `dormitory`，脚本在 `database/dormitory_mysql8.sql`。

12. 问：测试账号怎么来的？  
答：基础账号来自 `dormitory_mysql8.sql`，更多测试账号来自 `test_data.sql`。

13. 问：新增学生写入哪张表？  
答：写入 `student` 表，接口是 `POST /stu/add`。

14. 问：新增宿舍楼写入哪张表？  
答：写入 `dorm_build` 表，接口是 `POST /building/add`。

15. 问：房间床位保存在哪里？  
答：保存在 `dorm_room` 表，床位字段是 `first_bed` 到 `fourth_bed`。

16. 问：报修数据保存在哪里？  
答：保存在 `repair` 表，学生提交和管理员处理都操作这张表。

17. 问：调宿申请涉及哪些表？  
答：申请记录在 `adjust_room` 表，通过审核时还会更新 `dorm_room` 的床位和入住人数。

18. 问：权限菜单数据在哪些表？  
答：在 `sys_role`、`sys_menu`、`sys_role_menu` 三张表。

19. 问：图表数据从哪来？  
答：首页图表从 `dorm_build` 获取楼栋编号，从 `dorm_room.current_capacity` 汇总每栋楼人数。

### 13.4 登录权限类

20. 问：登录后怎么保持状态？  
答：后端把用户和身份存进 Session，前端把用户和身份存进 `sessionStorage`。

21. 问：Session 和 Cookie 怎么用？  
答：登录成功后服务端创建 Session，浏览器保存对应 Cookie，后续请求带 Cookie 找回 Session。

22. 问：未登录能不能直接访问后台？  
答：前端路由守卫会检查 `sessionStorage.user`，没有就跳转 `/Login`。

23. 问：不同角色为什么菜单不同？  
答：后端 `/permission/menus` 根据 Session 中的 `Identity` 查询 `sys_role_menu` 和 `sys_menu`，返回不同菜单树。

24. 问：新增一个角色要改什么？  
答：要新增 `sys_role`，配置 `sys_role_menu`，必要时补充前端 fallback 菜单和业务权限判断。

### 13.5 代码实现类

25. 问：Controller、Service、Mapper 分别负责什么？  
答：Controller 接收 HTTP 请求，Service 写业务逻辑，Mapper 负责数据库操作。

26. 问：MyBatis-Plus 起什么作用？  
答：简化单表增删改查和分页，例如 `BaseMapper.insert`、`selectPage`、`updateById`。

27. 问：分页怎么实现？  
答：后端用 MyBatis-Plus 的 `Page` 对象，配置在 `MybatisPlusConfig.java` 的分页插件。

28. 问：前端表格怎么渲染？  
答：页面用 Element Plus 的 `el-table`，请求返回的 `records` 赋值给表格数据。

29. 问：表单提交后流程是什么？  
答：前端校验表单，Axios POST/PUT 到后端，Controller 调 Service，Service 调 Mapper 写库，成功后前端重新 `load()`。

30. 问：个人中心怎么更新？  
答：`SelfInfo.js` 根据身份调用 `/admin/update`、`/stu/update` 或 `/dormManager/update`。

31. 问：水电费为什么学生只能看自己的？  
答：`WaterController.find` 和 `ElectricController.find` 如果身份是 `stu`，会先查学生所在宿舍，再按 `roomid` 过滤。

32. 问：宿舍人数统计怎么做？  
答：`DormRoomServiceImpl.selectHaveRoomStuNum` 汇总 `dorm_room.current_capacity`。

33. 问：空宿舍统计怎么做？  
答：`DormRoomServiceImpl.notFullRoom` 查询 `current_capacity < max_capacity` 的房间数量。

34. 问：调宿通过后怎么换床位？  
答：`DormRoomServiceImpl.adjustRoomUpdate` 清空原床位，目标床位写入学生账号，同时更新两个房间的 `current_capacity`。

### 13.6 跨平台与移动端类

35. 问：这是 App 还是 Web 应用？  
答：这是 Vue Web 应用，不是原生 App，但能在 PC 和移动端浏览器访问。

36. 问：为什么说它跨平台？  
答：同一套前端页面可以在 Windows、macOS、手机浏览器中运行，靠响应式 CSS 适配屏幕。

37. 问：移动端菜单如何适配？  
答：`Aside.vue` 在小屏下变为横向滚动菜单，`Layout.vue` 把布局从左右改为上下。

### 13.7 项目改进类

38. 问：项目还有什么不足？  
答：密码目前是明文存储，权限主要控制菜单显示，接口级权限和数据校验还可以增强。

39. 问：如何增强安全性？  
答：可以加入密码加密、后端拦截器、接口权限校验、参数校验和统一异常处理。

40. 问：如何部署上线？  
答：前端 `npm run build` 生成静态文件，后端 Maven 打包成 jar，部署到服务器并连接 MySQL。

41. 问：如果菜单不显示怎么办？  
答：先查 `/permission/menus` 返回，再查 Session 的 `Identity`，最后查 `sys_role_menu` 是否配置。

42. 问：如果首页数据显示 0 怎么查？  
答：先 curl `/stu/stuNum`、`/room/selectHaveRoomStuNum`，再看前端 Console 和 Network。

43. 问：如果学生没有宿舍会怎样？  
答：`/room/getMyRoom/{name}` 查不到床位会返回错误，学生“我的宿舍”就没有宿舍信息。

44. 问：访客登记有什么关联表吗？  
答：当前 `visitor` 是独立登记表，没有强外键，记录访客姓名、电话、来源城市、访问时间和事由。

45. 问：权限说明页面的数据从哪里来？  
答：`PermissionInfo.vue` 请求 `/permission/roles` 和 `/permission/roleMenus` 展示角色和菜单对应关系。

## 14. 重点功能答辩话术

### 14.1 项目介绍话术

本项目是一个高校宿舍管理系统，采用 Spring Boot、MySQL 8.0 和 Vue 3 + Vite 实现。系统围绕宿舍管理场景设计，有管理员、宿舍管理员和学生三种角色。管理员可以维护学生、宿管、楼宇、房间、公告、报修、调宿、水电费、卫生检查和访客信息；学生可以查看自己的宿舍，提交报修和调宿申请。项目既有基础增删改查，也有登录认证、Session 保存、动态菜单和移动端适配，比较完整地覆盖了课程要求。

### 14.2 技术架构话术

本项目采用前后端分离。前端在 8080 端口运行，使用 Vue 3、Vite、Element Plus 和 Axios；后端在 9090 端口运行，使用 Spring Boot 和 MyBatis-Plus；数据库是 MySQL 8.0。前端请求统一写成 `/api/...`，Vite 代理把它转发到后端。后端 Controller 接收请求，Service 处理业务逻辑，Mapper 通过 MyBatis-Plus 操作数据库，最后统一用 `Result` 返回 JSON。

### 14.3 数据流话术

以新增报修为例，学生在 `ApplyRepairInfo.vue` 页面填写报修标题和内容。前端 `ApplyRepairInfo.js` 先根据当前登录用户调用 `/room/getMyRoom/{username}` 获取宿舍楼和房间号，然后提交 `POST /repair/add`。后端 `RepairController.add` 接收 `Repair` 对象，调用 `RepairServiceImpl.addNewOrder`。如果状态和创建时间为空，后端会自动设置 `state` 为“未完成”，设置当前时间为 `order_buildtime`，最后通过 `RepairMapper.insert` 写入 `repair` 表。提交成功后前端重新调用 `/repair/find/{name}` 刷新列表。

### 14.4 权限控制话术

系统的权限分两部分。第一部分是登录状态，后端登录成功后把用户和身份放入 Session，前端也把用户和身份放入 `sessionStorage`，路由守卫根据它判断是否允许进入后台。第二部分是动态菜单，数据库里有 `sys_role`、`sys_menu`、`sys_role_menu` 三张权限表，后端 `/permission/menus` 根据当前 Session 中的角色查询菜单树，前端 `Aside.vue` 根据菜单树渲染侧边栏。这样管理员、宿管和学生看到的菜单就不一样。

### 14.5 移动端适配话术

本项目符合跨平台开发要求，因为它是基于 Vue 的 Web 应用，不依赖特定操作系统。PC 端可以用浏览器访问后台，手机端在同一局域网也可以通过电脑 IP 加 8080 端口访问。移动端适配主要通过 CSS 媒体查询实现，例如菜单在小屏下变为横向滚动，首页统计卡片从多列变单列，表格和弹窗宽度自动适配屏幕。

## 16. 项目可能存在的风险

可能被老师追问的点：

- 密码是明文存储。可以回答：课程项目重点是完整业务流程，后续可用 BCrypt 加密。
- 数据库没有显式外键。可以回答：当前通过字段做逻辑关联，方便测试数据导入；正式系统应增加外键或业务校验。
- 权限主要控制菜单显示。可以回答：当前已实现角色菜单权限，后续可加后端拦截器做接口级鉴权。
- Session 丢失后菜单兜底。可以回答：为了开发演示稳定，前端使用 `sessionStorage` 兜底，正式系统应统一以后端 Session 或 Token 为准。
- 图表没有使用 ECharts。可以回答：当前首页是 Vue + CSS 柱状图，数据是真实接口返回的，重点是统计数据来源和展示稳定性。
- 水电费中管理员扣费、非管理员充值的规则较简单。可以回答：这是课程演示规则，后续可细分宿管和学生权限。

建议提前检查：

- 三种角色都能登录。
- 首页四个统计卡片有真实数据。
- 动态菜单是否按角色变化。
- 学生提交报修和调宿是否能在管理员页面看到。
- 管理员审核调宿后，房间床位是否变化。
- 手机浏览器能否访问 `http://电脑IP:8080/Login`。

建议截图备用：

- 登录页。
- 管理员首页。
- 学生管理表格。
- 房间床位管理页面。
- 调宿申请审核页面。
- 权限说明页面。
- 手机端首页或菜单适配效果。
