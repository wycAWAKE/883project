# FAQ 步骤5：应用检索接入交付

日期：2026-11-17（Asia/Shanghai）。**步骤5完成：应用已具备可显式启用的BGE-M3索引与检索排序，真实只读联调通过。步骤6和R6尚未完成，模块保持Under development。**

## 实际行为

Spring注入的`FaqService`现在共用以下链路：

```text
本轮独立问题 / C5解析后的问题
 → 一次MySQL快照 → 启用/内容/官方来源过滤
 → TF-IDF原阈值准入 → 立即保留本轮标准答案供超时降级
 → BGE-M3向量排序（显式启用时）→ 最多3条本轮证据
 → 原DeepSeek生成/引用校验，或标准答案降级
```

**步骤5的实现选择：暂保留现有词法接收门槛。** 尚无经过校准的向量接收阈值，因此BGE只排序已经通过TF-IDF门槛的证据；完全缺少词法证据仍返回no_match，且不调用向量服务。0.35没有被套用成embedding阈值。向量成功时score是实际cosine；TF-IDF回退时score是词法分数，均不代表正确概率。纯语义候选接收、拒答策略及其效果比较留到步骤6，不把本步描述为已经提升了同义改写召回。

`/ask`、`/chat`和内部`retrieveContexts`均使用当前检索流程；四参数Service构造器保留给显式离线基线/旧测试，Spring使用五参数构造器注入新检索器。前端、API字段、C5规则、生成提示及DeepSeek配置均未改。

## 索引和故障边界

- 索引位于进程内，只保留FAQ ID与归一化向量，不新增数据库表、字段或依赖，不读取旧实验target向量文件。
- 文档表示继续使用`question + 空格 + keywords`。索引版本hash覆盖完整当前有效知识的ID、问题、答案、分类、关键词、来源标题/URL、启用状态、更新时间，以及固定模型/1024维/表示版本。
- 每次重新读取并过滤数据库。全量版本一致才复用；禁用、删除或任意上述字段变化后，下一次有有效候选的请求重建索引。答案/来源始终取本轮快照，不能用缓存旧答案。
- 新索引完整构建成功才原子发布；部分失败不发布。一个tryLock限制重建，并发请求不等待，直接使用本轮TF-IDF结果。运行期失败后冷却30秒，期间继续词法检索。
- 每批最多16段、3072 UTF-8输入字节；索引最多128条、8个文档批次和24576输入字节，查询另一次。超限回退原检索。当前40条知识构建需3批；暖索引每个有证据的问题只需1次查询向量请求。查询不缓存、不持久化。
- 固定官方端点和`BAAI/bge-m3`，只接受`SILICONFLOW_API_KEY`，无重试、重定向、旧凭据或付费型号回退。验证返回模型、维度、index唯一完整性、用量、有限非零向量及1MiB响应上限；缩放归一化覆盖极大/极小有限数值，避免旧试验工具的范数溢出问题。
- 向量子预算8秒受原35秒请求预算及取消状态约束，连接/读取单次超时最多3秒。**这是协作预算，不是硬终止保证**：底层DNS、写入、慢响应头等阻塞可能延迟工作线程/重建锁释放。外层Runner仍有最多4任务、无队列和有界HTTP等待；当前可靠词法摘录在向量I/O前发布，父超时仍可返回本轮答案并保留已解析话题。
- 服务重启清空索引，固定模型/维度/表示代码变化也会重建。同一个模型别名在服务端发生未通知更新无法自动识别，出现该情况需重启；本步不实现持久缓存、管理接口或定时刷新。

## 启用和回退

普通启动保持embedding关闭。单独启用`faq-embedding`可测试向量排序与标准答案；组合`faq-deepseek,faq-embedding`使用原DeepSeek生成。两者凭据独立，私有环境配置沿用现有方式。

```powershell
# 在springboot目录；密钥应已私有配置到此进程环境，不写入源码。
mvn spring-boot:run '-Dspring-boot.run.profiles=faq-deepseek,faq-embedding'
```

`SILICONFLOW_API_KEY`为必需的向量服务凭据，开启但缺少有效凭据会启动失败。设置`FAQ_EMBEDDING_ENABLED=false`可显式关闭该profile中的向量调用；或仅保留原`faq-deepseek` profile恢复原TF-IDF路径。不要用聊天Key替代向量Key。本轮未为用户留下新的后台服务或修改持久环境变量。

本机只读预检需要`FAQ_STEP5_DB_VERIFY=true`且显式选`FaqStep5PreflightIT`；真实专项需要`FAQ_STEP5_LIVE_VERIFY=true`且显式选`FaqSemanticRetrievalIT`，再次运行前需明确本轮调用范围并核对服务价格。普通`mvn test`不运行这些专项。
