## 数据和方法

1. 使用已审校40条公开知识和独立12题调参集（8个有答案、4个无答案）。不提交或用于此次选型计算固定40题评估集及12题C5样本。
2. 文档表示为`question + 空格 + keywords`，与TF-IDF相同；没有通过额外加入答案正文改变比较口径。
3. 52段文本共6121 UTF-8字节，按16/16/16/4分四批。每批最多16项、合计3072输入字节，全轮最多8次请求/20000字节/40000报告输入tokens。字节界限是保守试验限制，不是模型tokenizer的实测上界。
4. 响应需模型匹配、index唯一完整、1024维、有限非零向量；用量必须为有界整数，拒绝大整数溢出。固定官方HTTPS、无重定向/重试，连接3秒/读取30秒受35秒单批预算约束，响应最多1MiB。预算复用现有协作式检查，不承诺强行终止阻塞DNS/写入。
5. 同时记录两种检索不设接收阈值的Top1/Top3，另保留TF-IDF原0.35参考。embedding不照搬0.35；无答案题只记录相似度分布，不计算未经校准的拒答率。
6. 保存模型/维度、输入/语料/调参/向量SHA-256、用量和耗时。模型别名未来可能变更；hash可标识本次结果，不能保证以后重调用逐位相同。

TF-IDF原0.35阈值后的第一候选命中为4/8；不能将它与未经阈值过滤的7/8当作同口径对比。选择BGE-M3的项目依据是第一候选改善、Java真实可调用和当前免费；8题不是最终独立评估，更不是生成准确率。

- C04仍错：企业微信登录手机号问题，目标`CCNU-FAQ-034`排第二（0.61464），`CCNU-FAQ-017`第一（0.67361）。本步未为这个样本修改知识、标签或表示。
- 无答案C09–C12的最高cosine约0.42388、0.64649、0.54384、0.34871；C10当前补卡费仍与旧卡指南相似，相似不能证明当前费用有事实支持。阈值/拒答/候选冲突处理继续留到后续步骤。
- 四批耗时1927/393/266/156ms，是一次批量试验，不是线上单题P95。
- 40条float向量数值本体约160KiB，首版无需向量数据库；实际试验保存double数组JSON，文件更大。
