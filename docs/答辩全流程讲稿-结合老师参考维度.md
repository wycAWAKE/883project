## 1. 开场介绍

老师好，我的项目是“高校宿舍管理系统”。它是一个基于 B/S 架构的 Web 管理系统。B/S 就是浏览器/服务器架构，意思是用户不用安装软件，只需要打开浏览器访问系统。浏览器页面是前端，Spring Boot 后端负责处理业务，MySQL 数据库负责保存数据。

系统主要解决宿舍管理中人员信息、楼宇房间、床位、报修、调宿、水电费、卫生检查、访客登记、公告和权限菜单分散管理的问题。

系统分为三种角色：

- 管理员：负责学生、宿管、楼宇、房间、公告、报修、调宿、水电费、卫生检查、访客和权限说明。
- 宿舍管理员：负责日常宿舍事务，比如报修处理、调宿审核、访客登记、卫生检查。
- 学生：查看自己的宿舍，提交报修，提交调宿申请，查看水电费和卫生检查记录。

一句话总结这个系统：这是一个 Spring Boot + Vue 前后端分离的高校宿舍管理系统。前后端分离的意思是页面和后端服务分开写、分开启动；Vue 负责页面，Spring Boot 负责接口，Axios 负责从页面向后端发送请求，MySQL 负责保存数据。

## 2. 系统演示总路线：数据库 -> 后端 -> 前端

答辩时建议先讲整体链路，再开始点页面：

```text
MySQL 数据库 dormitory
  -> Spring Boot 后端 9090 端口
  -> Vue + Vite 前端 8080 端口
  -> 浏览器页面展示和操作
```

可以这样说：

我的数据保存在 MySQL 的 `dormitory` 数据库中。MySQL 可以理解成电子档案柜，`dormitory` 是这个系统专用的档案柜名字。后端 Spring Boot 通过 Controller、Service、Mapper 三层处理请求：Controller 是接待员，负责接收前端请求；Service 是办事员，负责处理业务规则；Mapper 是数据库操作员，负责真正查询或修改数据库。前端 Vue 页面通过 Axios 发送 HTTP 请求，HTTP 就是浏览器和服务器说话的规则。Vite 把 `/api` 代理到后端 `localhost:9090`，代理就是帮前端把请求转发给后端。后端返回 JSON，JSON 是前后端传数据的一种文本格式，前端再把这些数据渲染成表格、弹窗和菜单。

完整请求链路举例：

```text
用户点击学生信息页面
  -> StuInfo.js 调用 request.get("/stu/find")
  -> request.js 给接口加 /api
  -> Vite 代理到 http://localhost:9090/stu/find，也就是转发给后端
  -> StudentController 接收请求，Controller 就是后端入口
  -> StudentServiceImpl 处理分页和搜索，ServiceImpl 就是真正写业务规则的地方
  -> StudentMapper 通过 MyBatis-Plus 查询 student 表，Mapper 就是操作数据库的接口
  -> MySQL 返回数据，MySQL 就是数据库软件
  -> Result.success(page) 返回 JSON，Result 是统一返回格式，JSON 是前后端传数据格式
  -> 前端 Element Plus 表格展示数据，Element Plus 是页面组件库
```

## 3. 数据库设计思路

数据库设计我是按老师给的步骤来的：

1. 需求分析：先分析宿舍管理需要哪些业务，也就是先想清楚系统要解决什么问题，比如学生、宿管、宿舍楼、房间、报修、调宿、水电费、卫生检查、访客、公告和权限。
2. 概念结构设计：把系统拆成实体。实体就是系统里要管理的对象，例如学生、宿管、楼宇、房间、报修单、调宿申请、菜单角色。
3. 逻辑结构设计：把实体转换成数据表。数据表就是数据库里的表格，字段就是表格里的列。
4. 物理结构设计：设置主键、字段类型、唯一业务编号和必要约束。主键就是每条记录的唯一编号。
5. 数据库实施：通过 `database/dormitory_mysql8.sql` 创建数据库和表。SQL 是操作数据库的命令。
6. 维护与优化：补充 `test_data.sql` 测试数据，增加权限表支持动态菜单。动态菜单就是不同角色登录后看到不同菜单。

核心表可以这样讲：

| 类型 | 表名 | 作用 |
| --- | --- | --- |
| 用户表 | `admin`、`student`、`dorm_manager` | 保存三类登录账号 |
| 宿舍基础表 | `dorm_build`、`dorm_room` | 保存宿舍楼、房间和床位 |
| 业务表 | `repair`、`adjust_room`、`dorm_water`、`dorm_electric`、`dorm_check`、`visitor`、`notice` | 保存报修、调宿、水电费、卫生检查、访客和公告 |
| 权限表 | `sys_role`、`sys_menu`、`sys_role_menu` | 控制不同角色看到的菜单 |

主键和关联说明：

- `student.username` 是学生账号，也用于房间床位字段和业务申请人字段。
- `dorm_build.dormbuild_id` 是楼宇编号，`dorm_room.dormbuild_id` 通过这个编号关联宿舍楼。
- `dorm_room.dormroom_id` 是房间号，水电费和卫生检查通过 `roomid` 关联房间。
- `sys_role_menu` 通过 `role_code` 和 `menu_id` 关联角色与菜单。

可以补一句：

本项目没有强制写大量 `FOREIGN KEY` 外键。外键就是数据库里用来维护两张表关系的约束。我的项目更多是通过字段命名和业务逻辑做逻辑关联，逻辑关联就是代码里约定两个字段有关联，但数据库不强制检查。这样在课程演示和测试数据导入时更灵活，但答辩时我知道主键负责唯一标识，外键负责维护表之间一致性。

## 4. 前端和后端框架怎么讲

### 后端 Spring Boot

后端分层结构：

```text
controller  接收前端 HTTP 请求
service     处理业务逻辑
mapper      操作数据库
entity      映射数据库表
common      Result 统一返回格式
config      MyBatis-Plus 分页插件配置
```

答辩说法：

后端使用 Spring Boot，Spring Boot 是 Java 后端框架，可以快速搭建接口服务。启动类是 `SpringbootApplication.java`，可以理解成后端程序的入口。Controller 用 `@RestController` 和 `@GetMapping`、`@PostMapping` 接收请求，其中 GET 一般查数据，POST 一般提交数据。ServiceImpl 写业务逻辑，业务逻辑就是系统处理事情的规则。Mapper 继承 MyBatis-Plus 的 `BaseMapper`，可以快速实现增删改查和分页查询。最后用 `Result` 统一返回 `code`、`msg`、`data` 格式的 JSON。

### 前端 Vue

前端结构：

```text
views       页面组件
assets/js   每个页面的业务逻辑
router      页面路由和登录拦截
utils       Axios 请求封装
components  头部、侧边栏、图表等公共组件
assets/css  样式和移动端适配
```

答辩说法：

前端使用 Vue 3 + Vite。Vue 是写页面的框架，组件化就是把页面拆成一个个可复用的小模块。Vite 是前端启动和打包工具。Element Plus 提供表格、表单、按钮、弹窗等 UI 组件，UI 就是用户看到的界面。Vue Router 负责页面跳转和登录拦截，登录拦截就是没登录不让访问后台页面。Axios 负责请求后端接口，接口就是前端调用后端的地址。`request.js` 统一配置 `baseURL: "/api"`，`vite.config.js` 再把 `/api` 转发到后端 `http://localhost:9090`。

### B/S 架构

老师问 B/S 架构时可以这样答：

B/S 是 Browser/Server，也就是浏览器/服务器架构。用户不需要安装专门客户端，只要通过浏览器访问前端页面，页面再请求后端服务。我的系统就是 B/S 架构，PC 浏览器和手机浏览器都可以访问同一套系统。

### 第一步：展示登录页和三种角色

2. 展示登录页。
3. 说明有管理员、宿舍管理员、学生三种身份。

讲解：

### 第二步：管理员登录，展示首页统计

操作：

## 6. 核心功能技术实现问答

### Q1：你的系统是怎么和数据库交互的？

答：

前端通过 Axios 发送 HTTP 请求，后端 Controller 接收请求，然后调用 Service 处理业务逻辑，Service 再调用 Mapper。Mapper 使用 MyBatis-Plus 执行 SQL 操作 MySQL，数据库返回结果后，后端用 `Result` 统一封装成 JSON，再返回给前端页面展示。

以学生查询为例：

```text
StuInfo 页面 -> request.get("/stu/find") -> StudentController -> StudentServiceImpl -> StudentMapper -> student 表
```

### Q2：Controller、Service、Mapper 分别有什么作用？

答：

Controller 是前后端交互入口，负责接收请求和参数。Service 是业务逻辑层，负责判断、校验、分页、状态处理等逻辑。Mapper 是持久层，负责和 MySQL 数据库交互。这样分层后代码更清晰，不会把页面请求、业务判断和数据库操作混在一起。

### Q3：MyBatis-Plus 在你的项目中做了什么？

答：

MyBatis-Plus 简化了数据库操作。我的 Mapper 继承 `BaseMapper` 后，可以直接使用 `insert`、`deleteById`、`updateById`、`selectPage` 等方法，不需要为每一个基础 CRUD 都手写 SQL。分页查询时使用 `Page` 对象，条件查询时使用 `QueryWrapper`。

### Q4：GET 和 POST 在你的项目里怎么区分？

答：

GET 主要用于查询数据，比如 `/stu/find` 查询学生列表、`/repair/find` 查询报修列表、`/permission/menus` 查询菜单。POST 主要用于新增或提交数据，比如 `/repair/add` 提交报修、`/adjustRoom/add` 提交调宿申请、`/admin/login` 登录。简单说，查询用 GET，新增、登录、提交表单用 POST。

### Q5：你的登录是怎么实现的？

答：

前端登录页根据选择的身份拼接接口，例如管理员是 `/admin/login`，宿管是 `/dormManager/login`，学生是 `/stu/login`。后端对应 Controller 查询各自用户表，用户名和密码匹配后，把当前用户和身份保存到 `HttpSession` 中。前端也把 `user` 和 `identity` 保存到 `sessionStorage`。后续页面请求菜单和用户信息时，可以从 Session 或 sessionStorage 恢复登录状态。

### Q6：权限控制是怎么做的？

答：

权限控制主要体现在菜单权限上。数据库有 `sys_role`、`sys_menu`、`sys_role_menu` 三张表。后端 `/permission/menus` 根据当前登录角色查询对应菜单，并组装成父子菜单树。前端 `Aside.vue` 根据返回的数据动态渲染菜单。管理员、宿管、学生看到的菜单不同，所以能体现角色权限差异。

### Q7：学生报修功能怎么实现？

答：

业务上，学生填写报修标题和内容，提交后管理员或宿管可以看到并处理。

技术上，学生页面 `ApplyRepairInfo.js` 先调用 `/room/getMyRoom/{username}` 获取自己的宿舍楼和房间号，然后点击提交时调用 `request.post("/repair/add", this.form)`。后端 `RepairController.add` 用 `@RequestBody Repair repair` 接收 JSON，调用 `RepairServiceImpl.addNewOrder`，最后通过 `RepairMapper.insert` 写入 `repair` 表。提交成功后前端刷新列表。

### Q8：调宿申请通过后，数据库会发生什么变化？

答：

调宿通过后至少涉及两部分：一是 `adjust_room` 表的申请状态变成通过，二是 `dorm_room` 表的床位信息发生变化。后端在 `AdjustRoomController.update/{state}` 中判断如果是通过，就调用 `DormRoomServiceImpl.adjustRoomUpdate`。这个方法会把原房间对应床位清空，把目标房间对应床位写入学生账号，并同步更新两个房间的当前入住人数。

### Q9：房间床位是怎么保存的？

答：

房间信息保存在 `dorm_room` 表。每个房间有 `first_bed`、`second_bed`、`third_bed`、`fourth_bed` 四个床位字段，用来保存学生账号。比如某个学生住在 301 的一号床，那么 `dormroom_id=301` 这一行的 `first_bed` 就是该学生的 username。

### Q10：为什么你的系统可以说是跨平台？

答：

因为它是 B/S 架构的 Web 应用，不依赖某一个桌面客户端。只要设备有浏览器，并能访问前端地址，就可以使用系统。PC 浏览器可以完整使用后台页面，手机浏览器也可以访问同一套 Vue 页面。移动端通过 CSS 媒体查询和响应式布局适配。

### Q11：Vite 代理 `/api` 是什么作用？

答：

前端开发服务器运行在 8080，后端运行在 9090，直接请求会涉及跨域。项目中 `request.js` 的 `baseURL` 是 `/api`，页面写接口时只写 `/stu/find`。Vite 在 `vite.config.js` 中把 `/api` 转发到 `http://localhost:9090`，所以浏览器请求 `/api/stu/find`，实际由 Vite 转发给后端 `/stu/find`。

### Q12：Result 统一返回有什么好处？

答：

`Result` 统一返回 `code`、`msg`、`data`，前端不用针对每个接口写不同的判断逻辑。比如 `code` 为 `"0"` 表示成功，`data` 放真实数据，`msg` 放错误信息。这样前后端约定清楚，页面可以统一弹出成功或失败提示。

### Q13：如果页面没有数据，你会怎么排查？

答：

我会按链路排查：

1. 看 MySQL 是否启动，数据库里有没有数据。
2. 看后端 9090 是否启动成功。
3. 直接访问或 curl 后端接口，看接口是否返回 JSON。
4. 看前端 8080 是否启动成功。
5. 打开浏览器 Network，检查 `/api/...` 请求是否 200。
6. 如果是登录后页面，检查 Session 和 sessionStorage 里是否有用户身份。

### Q14：如果老师问你项目有什么不足，怎么回答？

答：

当前系统已经实现了主要业务流程和角色交互，但还有可以优化的地方。比如密码目前是明文保存，正式系统应该加密；数据库主要使用逻辑关联，没有大量强外键；权限主要控制菜单显示，还可以继续扩展到按钮级权限和接口级权限；移动端是 Web 响应式适配，不是原生 App。后续可以从安全性、权限细粒度、数据约束和移动端体验继续完善。

## 7. 老师可能按知识点追问

### 数据库设计包括哪些步骤？

答：

需求分析、概念结构设计、逻辑结构设计、物理结构设计、数据库实施、维护与优化。我的项目就是先分析宿舍管理需求，再设计学生、宿管、宿舍楼、房间、报修、调宿等实体，最后转换成 MySQL 表，并通过 SQL 脚本创建和维护。

### 主键和外键的作用是什么？

答：

主键用于唯一标识一条记录，比如 `student.username` 唯一标识一个学生，`dorm_room.dormroom_id` 唯一标识一个房间。外键用于表与表之间关联，保证数据一致性。我的项目里更多使用逻辑外键，例如 `dorm_room.dormbuild_id` 对应 `dorm_build.dormbuild_id`，`repair.repairer` 对应学生姓名或申请人信息。

### Tomcat 在项目中有什么作用？

答：

Spring Boot 内置 Tomcat。它作为 Web 应用服务器和 Servlet 容器，负责监听后端端口、接收 HTTP 请求、把请求分发给对应的 Controller，并把 Controller 返回的数据响应给前端。

### Vue Router 有什么作用？

答：

Vue Router 负责前端页面跳转。我的项目在 `router/index.js` 中配置了 `/home`、`/stuInfo`、`/repairInfo`、`/applyRepairInfo` 等路径和页面组件的对应关系。同时还写了路由守卫，如果没有登录信息，就跳转到登录页。

### Axios 有什么作用？

答：

Axios 是前端网络请求工具。我的项目在 `utils/request.js` 里统一封装 Axios，配置了 `baseURL: "/api"`、超时时间和响应拦截器。这样每个页面只需要调用 `request.get` 或 `request.post`，不用重复写完整请求配置。

### Entity 是什么？

答：

Entity 是实体类，负责和数据库表字段映射。比如 `Student` 类对应 `student` 表，`Repair` 类对应 `repair` 表。后端从数据库查出来的数据会封装成 Entity 对象，前端传来的 JSON 也可以通过 `@RequestBody` 封装成实体对象。

### dist 是什么？

答：

`dist` 是前端打包后的发布目录。开发时写的是 `src` 里的 Vue 源码，执行 `npm run build` 后，Vite 会把源码打包压缩成 `dist`，里面有最终部署用的 HTML、CSS、JS 文件。

### Nginx 可以在这个项目中做什么？

答：

如果正式部署，可以把 Vue 打包后的 `dist` 放到 Nginx，让 Nginx 托管前端静态页面；同时配置反向代理，把 `/api` 请求转发给 Spring Boot 后端。开发阶段我用 Vite 代理实现类似效果。

### RESTful 接口是什么？

答：

RESTful 是一种接口设计风格，用 URL 表示资源，用 HTTP 方法表示操作。比如查询用 GET，新增用 POST，修改用 PUT，删除用 DELETE。我的项目里 `/repair/find` 查询报修，`/repair/add` 新增报修，`/repair/update` 修改报修，`/repair/delete/{id}` 删除报修。

我的系统从数据库、后端到前端形成了完整链路。数据库负责保存宿舍管理数据，后端 Spring Boot 负责接口和业务逻辑，前端 Vue 负责页面展示和用户操作。系统实现了管理员、宿管、学生三种角色，并通过报修和调宿功能体现了不同角色之间的数据交互。项目也做了 PC 和移动端页面适配，符合跨平台 Web 应用的特点。
