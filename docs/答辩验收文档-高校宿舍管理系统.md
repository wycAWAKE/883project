# 高校宿舍管理系统答辩验收文档

## 一、项目概述

本项目名称是“高校宿舍管理系统”，属于管理系统类课程设计。系统围绕学校宿舍日常管理场景开发，主要解决学生住宿信息维护、宿舍楼与房间管理、报修处理、调宿申请、水电费记录、卫生检查、访客登记、公告发布、角色菜单权限控制等问题。

系统采用前后端分离结构：

- 前端：Vue 3、Vite、Element Plus、Vue Router、Axios、OverlayScrollbars。
- 后端：Spring Boot 2.6.3、Spring MVC、MyBatis-Plus、MySQL 8.0。
- 数据库：MySQL，数据库名为 `dormitory`。
- 开发端口：前端 `8080`，后端 `9090`。

一句话介绍：

> 这是一个基于 Spring Boot + Vue 的高校宿舍管理系统，支持管理员、宿舍管理员、学生三种角色，通过前后端接口完成宿舍、学生、维修、调宿、水电费、卫生检查等数据的增删改查和业务流转。

## 四、前后端通信方式

### 1. 前端怎样请求后端？

前端统一使用 Axios 封装请求，文件位置：

```text
vue/src/utils/request.js
```

关键点：

- `baseURL: '/api'`
- `timeout: 5000`
- `withCredentials: true`
- 响应拦截器统一返回 `response.data`

前端页面里不用写完整后端地址，只写类似：

```js
request.get("/stu/find")
request.post("/admin/login", this.form)
request.post("/check/add", this.form)
```

### 2. `/api` 怎么转发到后端？

前端开发服务器通过 Vite 代理转发接口请求，配置文件：

```text
vue/vite.config.js
```

核心配置：

```js
proxy: {
  '/api': {
    target: 'http://localhost:9090',
    changeOrigin: true,
    rewrite: path => path.replace(/^\/api/, '')
  }
}
```

举例：

前端请求：

```text
GET /api/stu/find
```

Vite 实际转发给后端：

```text
GET http://localhost:9090/stu/find
```

所以移动端和 Web 端的通信方式本质一样：都是浏览器端通过 Axios 发送 HTTP 请求，后端 Spring Boot 返回 JSON 数据。


```java

session.setAttribute("User", o);
```

### 3. Session 和 Cookie 是怎么工作的？

后端使用的是 Spring Boot 默认的 `HttpSession`。

流程如下：

1. 前端提交用户名、密码、身份。
2. 后端查询对应表，例如管理员查 `admin` 表，学生查 `student` 表，宿管查 `dorm_manager` 表。
3. 登录成功后，后端把用户对象和身份保存到 Session。
4. 浏览器保存后端返回的 `JSESSIONID` Cookie。
5. 前端 Axios 设置了 `withCredentials: true`，后续请求会自动带上 Cookie。
6. 后端通过 Cookie 找到对应 Session，再读取 `Identity` 和 `User`。

前端同时也把用户信息保存到浏览器 `sessionStorage`：

```js
window.sessionStorage.setItem("user", JSON.stringify(res.data));
window.sessionStorage.setItem("identity", JSON.stringify(this.form.identity));
```

这个主要用于前端路由守卫和页面展示，真正后端识别登录态依靠的是服务端 Session。

### 4. 退出登录在哪里？

后端退出接口：

```text
springboot/src/main/java/com/example/springboot/controller/MainController.java
```

核心代码：

```java
session.removeAttribute("User");
session.removeAttribute("Identity");
```

### 2. 不同角色菜单为什么不一样？

侧边栏组件：

```text
vue/src/components/Aside.vue
```

页面初始化时会请求：

```text
GET /permission/menus
```

后端权限接口：

```text
springboot/src/main/java/com/example/springboot/controller/PermissionController.java
```

后端从 Session 里取当前角色：

```java
String roleCode = (String) session.getAttribute("Identity");
```

然后根据三张权限表查询菜单：

```text
sys_role
sys_menu
sys_role_menu
```

核心 SQL 逻辑是：

```sql
FROM sys_menu m
JOIN sys_role_menu rm ON m.id = rm.menu_id
WHERE rm.role_code = ?
```

所以管理员、宿管、学生看到的菜单不同，本质是数据库 `sys_role_menu` 表给不同角色分配了不同菜单。

## 九、典型业务数据是怎么进入数据库的？

### 问题 1：学生信息这条数据是怎么进数据库的？

前端页面：

```text
vue/src/views/StuInfo.vue
vue/src/assets/js/StuInfo.js
```

请求接口：

```text
POST /stu/add
```

后端位置：

```text
StudentController.add()
StudentServiceImpl.addNewStudent()
```

数据库表：

```text
student
```

代码链路：

1. 管理员在学生信息页面点击新增。
2. 前端表单收集 `username`、`password`、`name`、`age`、`gender`、`phoneNum`、`email`。
3. Axios 发送 `POST /api/stu/add`。
4. Vite 转发到 `http://localhost:9090/stu/add`。
5. `StudentController.add()` 接收 `@RequestBody Student student`。
6. 调用 `studentService.addNewStudent(student)`。
7. `StudentServiceImpl.addNewStudent()` 调用 `studentMapper.insert(student)`。
8. MyBatis-Plus 根据 `Student` 实体映射插入 `student` 表。

## 十、常见答辩问题与回答

### 1. 这个系统整体架构是什么？

回答：

> 系统是前后端分离架构。前端使用 Vue 3 + Vite + Element Plus 负责页面展示和用户交互；后端使用 Spring Boot + Spring MVC 提供 REST 接口；数据库使用 MySQL 保存学生、宿舍、报修、调宿、水电费、卫生检查等数据。前端通过 Axios 请求 `/api`，Vite 把 `/api` 代理到后端 `9090` 端口。

### 2. 前端和后端怎么通信？

回答：

> 前端统一使用 `vue/src/utils/request.js` 中封装的 Axios。所有接口都加 `/api` 前缀，例如 `/api/stu/find`。Vite 在 `vue/vite.config.js` 中配置代理，把 `/api` 请求转发到 `http://localhost:9090`，并去掉 `/api` 前缀。后端 Controller 接收请求后返回统一 JSON。

### 3. 后端返回的数据格式是什么？

回答：

> 后端统一用 `Result` 类封装返回结果，位置是 `springboot/src/main/java/com/example/springboot/common/Result.java`。格式包括 `code`、`msg`、`data` 三个字段。成功时 `code` 是 `"0"`，失败时返回 `"-1"` 和错误信息。

### 4. 登录状态是怎么保存的？

回答：

> 登录成功后，后端把用户对象和身份保存到服务端 Session 中，字段是 `User` 和 `Identity`。浏览器端通过 Cookie 保存 `JSESSIONID`，Axios 设置了 `withCredentials: true`，所以后续请求会自动带 Cookie。前端同时把用户信息保存到 `sessionStorage`，用于路由守卫和页面显示。

### 5. 为什么不同用户看到的菜单不同？

回答：

> 菜单权限由三张表控制：`sys_role`、`sys_menu`、`sys_role_menu`。登录后后端从 Session 里取 `Identity`，例如 `admin`、`dormManager`、`stu`，再到 `sys_role_menu` 查询这个角色拥有的菜单。前端侧边栏请求 `/permission/menus` 后动态渲染菜单。

### 6. 首页的学生统计从哪张表来？

回答：

> 首页学生统计调用 `/stu/stuNum`，后端在 `StudentServiceImpl.stuNum()` 中统计 `student` 表中学生账号数量。

### 7. 首页住宿人数从哪张表来？

回答：

> 住宿人数调用 `/room/selectHaveRoomStuNum`，后端在 `DormRoomServiceImpl.selectHaveRoomStuNum()` 中统计 `dorm_room.current_capacity` 的总和。

### 8. 首页空宿舍统计是什么意思？

回答：

> 这里统计的是还有空床位的房间数量。后端查询 `dorm_room` 表，条件是 `current_capacity < max_capacity`。

### 9. 宿舍学生人数分布图的数据来自哪里？

回答：

> 图表先调用 `/building/getBuildingName` 获取 `dorm_build` 表里的楼栋名称，再调用 `/room/getEachBuildingStuNum/{num}` 按楼栋统计 `dorm_room` 表中 `current_capacity` 的总和。

### 10. 一条卫生检查数据怎么进入数据库？

回答：

> 管理员或宿管点击卫生检查页面的新增按钮，前端调用 `POST /check/add`。后端 `CheckController.add()` 从 Session 中取当前登录用户作为 `operatorName`，自动生成当前时间作为 `date`，然后调用 `CheckServiceImpl.addNewOrder()`，最终通过 MyBatis-Plus 的 `checkMapper.insert(check)` 插入 `dorm_check` 表。

### 11. 一条调宿申请数据怎么进入数据库？

回答：

> 学生在“申请调宿”页面提交目标房间和床位，前端调用 `POST /adjustRoom/add`。后端 `AdjustRoomServiceImpl.addApply()` 自动设置状态为“未处理”，设置申请时间，然后插入 `adjust_room` 表。

### 12. 调宿审核通过后，为什么学生的宿舍会变化？

回答：

> 审核通过时前端调用 `PUT /adjustRoom/update/{state}`，后端如果判断是通过，就先调用 `DormRoomServiceImpl.adjustRoomUpdate()` 更新 `dorm_room` 表：原床位清空、原房间人数减一、目标床位写入学生账号、目标房间人数加一。然后再更新 `adjust_room` 表中的审核状态。

### 13. 学生只能看到自己的数据是怎么实现的？

回答：

> 部分接口会根据 Session 里的身份做过滤。例如卫生检查查询 `/check/find` 中，如果 `Identity` 是 `stu`，后端会先根据当前学生 username 查他的宿舍，再只查询这个宿舍的卫生检查记录。

### 14. MyBatis-Plus 在项目中起什么作用？

回答：

> MyBatis-Plus 简化了数据库操作。实体类用 `@TableName`、`@TableId`、`@TableField` 映射数据库表和字段，Service 中通过 `selectPage`、`selectOne`、`insert`、`updateById`、`deleteById` 完成增删改查，不需要每个简单 SQL 都手写 XML。

### 15. 为什么前端请求写 `/stu/find`，不是完整地址？

回答：

> 因为 Axios 封装里配置了 `baseURL: '/api'`，Vite 代理又把 `/api` 转发到后端 `9090`。所以页面只需要写业务路径 `/stu/find`，最终请求会变成 `http://localhost:9090/stu/find`。

### 16. 移动端适配是怎么做的？

回答：

> 前端主要通过 CSS 媒体查询和响应式布局完成移动端适配。布局文件 `Layout.vue` 在小屏幕下改成顶部栏、横向菜单、内容滚动区。表单、卡片、表格在 `global.css` 中针对 `max-width: 768px` 做了宽度和间距调整。另外使用 OverlayScrollbars 美化滚动条，提升 Web 和移动端滚动体验。

### 17. OverlayScrollbars 用在哪里？

回答：

> OverlayScrollbars 用在主内容滚动区和侧边菜单滚动区。主内容区在 `vue/src/layout/Layout.vue` 中用 `OverlayScrollbarsComponent` 包裹，侧边栏在 `vue/src/components/Aside.vue` 中包裹。滚动条主题在 `vue/src/assets/css/global.css` 中定义为 `os-theme-zijin`。

### 18. 如果老师问“数据库里的这条测试数据哪里来的”怎么答？

回答：

> 项目初始化数据来自 `database/dormitory_mysql8.sql` 和 `database/test_data.sql`。例如管理员、学生、宿管、宿舍楼、宿舍房间、公告、报修、水电费和卫生检查的基础数据都是脚本中 `INSERT INTO ...` 插入的。系统运行后，页面上的新增、编辑、删除操作会通过 Controller 和 Service 写入数据库。

### 19. 如果老师问“代码在哪里”怎么快速定位？

回答：

> 可以按“页面 - JS - Controller - Service - Mapper - 数据库表”的顺序找。例如卫生检查页面在 `vue/src/views/CheckInfo.vue`，逻辑在 `vue/src/assets/js/CheckInfo.js`，后端接口在 `CheckController.java`，业务层在 `CheckServiceImpl.java`，最终操作 `dorm_check` 表。

### 20. 如果老师问“为什么 `stu1` 我的宿舍报错”怎么答？

回答：

> 这是测试数据导致的问题，不是前后端通信失败。`DormRoomServiceImpl.judgeHadBed()` 使用 MyBatis-Plus 的 `selectOne` 查询某个学生在哪个床位，如果一个学生在 `dorm_room` 表中被重复分配到多个床位，`selectOne` 就会报“期望一条记录但查到多条”。演示时使用 `test_stu01`，或者清理 `stu1` 的重复床位数据即可。

## 十三、AI 生成的额外练习题

### 1. 为什么项目要做前后端分离？

答：

前后端分离可以让页面展示和业务接口解耦。前端专注用户交互和界面美化，后端专注业务逻辑和数据库操作。这样 Web 端和移动端可以共用同一套后端接口，也方便调试和维护。

### 2. 为什么不用直接在前端操作数据库？

答：

浏览器不能也不应该直接操作数据库。数据库账号密码如果暴露在前端会有安全风险，而且业务校验、权限判断、数据一致性都需要在后端完成。所以前端只发送请求，后端统一处理数据库操作。

### 3. Session 和 token 有什么区别？本系统用的是哪种？

答：

Token 通常由前端保存，后端通过解析 token 判断用户身份；Session 是后端保存登录状态，浏览器只保存一个 Session ID。本系统主要使用 Spring Boot 的 `HttpSession`，浏览器通过 `JSESSIONID` Cookie 维持会话。

### 4. MyBatis-Plus 的 `selectOne` 有什么风险？

答：

`selectOne` 要求查询结果只能有一条。如果数据库中有重复数据，查询到多条就会报错。所以像 `judgeHadBed(username)` 这种查询学生床位的方法，理论上要保证一个学生只能被分配到一个床位，或者改成 `selectList` 后再做业务判断。

### 5. 调宿审核为什么要同时更新两张表？

答：

`adjust_room` 表保存申请记录和审核状态，`dorm_room` 表保存真实床位分配。如果只更新申请表，学生实际宿舍不会改变；如果只更新房间表，又没有审核记录。因此通过后需要同时更新两张表。

### 6. 系统有没有权限控制？

答：

有。菜单层面通过 `sys_role`、`sys_menu`、`sys_role_menu` 控制不同角色显示不同菜单。接口层面部分接口会根据 Session 中的 `Identity` 和 `User` 做过滤，比如学生只能查看自己宿舍的卫生检查和水电费记录。

### 7. 如果前端页面刷新后还能保持登录吗？

答：

可以。前端把用户对象和身份保存到 `sessionStorage`，刷新页面后路由守卫可以继续读取。后端 Session 只要没有过期，浏览器请求时也会继续带 `JSESSIONID` Cookie，接口仍然能识别用户。

### 8. 数据库初始化脚本的作用是什么？

答：

初始化脚本用于创建数据库表和插入演示数据。答辩前执行脚本可以保证系统有管理员、学生、宿管、宿舍楼、房间、公告、报修、卫生检查等基础数据，方便现场演示。

## 十五、一分钟总结稿

老师好，我的课程设计是一个高校宿舍管理系统，采用 Spring Boot + Vue 前后端分离开发。系统分为管理员、宿舍管理员和学生三种角色。管理员可以维护学生、宿管、楼宇、房间、公告、报修、调宿、水电费和卫生检查等数据；宿管主要负责日常宿舍管理；学生可以查看个人宿舍、提交报修和调宿申请。

系统前端使用 Vue 3、Element Plus 和 Axios，后端使用 Spring Boot、Spring MVC 和 MyBatis-Plus，数据库使用 MySQL。前端统一请求 `/api`，通过 Vite 代理转发到后端 `9090` 端口。登录成功后，后端使用 Session 保存 `User` 和 `Identity`，浏览器通过 Cookie 维持会话，前端通过 sessionStorage 做页面状态和路由守卫。

首页统计数据来自数据库：学生统计来自 `student` 表，住宿人数和空床位来自 `dorm_room` 表，报修统计来自 `repair` 表，宿舍公告来自 `notice` 表，宿舍人数分布图通过 `dorm_build` 和 `dorm_room` 两张表统计生成。整个系统覆盖了管理系统常见的增删改查、多角色菜单权限、跨平台响应式页面和实际业务流程。
